# Ship of Harkinian on a Physical Apple TV

This is the reproducible workflow for the existing Apple-platform fork. It
keeps the legally obtained Ocarina of Time ROM and extracted Nintendo assets
outside the repository.

## Prerequisites

- Apple Silicon Mac with Xcode and an active Apple Developer account.
- Apple TV paired with Xcode for wireless development.
- A legally obtained compatible Ocarina of Time ROM, kept outside the repo.
- Homebrew only for host dependencies that the fork does not provide.

Check the host tools:

```sh
xcodebuild -version
cmake --version
python3 --version
ninja --version
xcrun --sdk appletvos --show-sdk-version
```

The current validation host has Xcode 27, tvOS SDK 27.0, CMake 4.0.3, and
Python 3.14.6. Ninja is not required by the generated Xcode workflow.

## Clone and inspect

```sh
git clone --recursive https://github.com/linkzenic/Ship-of-Harkinian-iOS.git
cd Ship-of-Harkinian-iOS
git submodule update --init --recursive
git switch -c tvos-device-validation
```

Read `README.md`, `docs/IOS_PORT.md`, the Apple build scripts, and the tvOS
source before changing anything.

## Generate the Ship support archive

The Apple build expects a locally generated ROM-free `soh.o2r`. Generate it
with the repository’s existing CMake target; do not copy a ROM or extracted
Nintendo data into the repository:

```sh
cmake -S . -B build-host -GXcode \
  -DCMAKE_C_COMPILER=/usr/bin/clang \
  -DCMAKE_CXX_COMPILER=/usr/bin/clang++ \
  -DCMAKE_PREFIX_PATH=/opt/homebrew \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=13.3 \
  -DCMAKE_CXX_STANDARD=20 \
  -DSPDLOG_USE_STD_FORMAT=OFF \
  -DSPDLOG_FMT_EXTERNAL=ON \
  -DCMAKE_BUILD_TYPE=Release \
  -DENABLE_SCRIPTING=OFF \
  -DBUILD_REMOTE_CONTROL=OFF
cmake --build build-host --target GenerateSohOtr --config Release
```

Install only missing host libraries required by this existing build graph. On
the validation host, the required Homebrew packages included fmt, spdlog,
glew, nlohmann-json, tinyxml2, libogg, libvorbis, opusfile, libzip, SDL2, and
opus.

## Configure signing

Do not commit a personal team identifier. Supply it through the environment or
Xcode’s local signing settings:

```sh
export DEVELOPMENT_TEAM=<TEAM_ID>
```

For the initial physical-device milestone, disable CloudKit unless the
developer team owns a registered iCloud container. The fork defaults to the
shared container `iCloud.com.shipofharkinian.shared`, which is not available to
arbitrary developer teams:

```sh
export SOH_ENABLE_ICLOUD=OFF
```

This keeps local saves enabled while omitting the CloudKit entitlement. Enable
CloudKit later only after registering a developer-owned container and granting
the tvOS App ID access to it.

The default tvOS bundle identifier is `com.shipofharkinian.tvos`. If it is not
available to the developer account, use the fork’s `TVOS_BUNDLE_ID` override in
the local build environment. Do not change shared project defaults just for a
personal App ID.

## Build the signed tvOS app

For Xcode versions whose tvOS SDK no longer accepts the fork’s default 14.0
deployment target, provide the minimum supported target locally:

```sh
DEPLOYMENT_TARGET=15.0 \
DEVELOPMENT_TEAM=<TEAM_ID> \
SOH_ENABLE_ICLOUD=OFF \
scripts/build-ios.sh --tvos-device
```

The expected output is:

```text
build-tvos-device/soh/Release-appletvos/Ship of Harkinian.app
```

The build script and generated CMake project remain authoritative; do not
maintain a second hand-edited Xcode project.

## Install and launch

Open the generated Xcode project or use Xcode’s normal Run workflow after
selecting the paired Apple TV as the destination. Confirm that the app is
development-signed for the selected team.

Attach the Xcode console and record the first launch. The initial test should
check SDL, Metal, surface creation, audio, writable application storage, the
first-run interface, and stability without game data.

## Import game data

The existing tvOS file server is started by the Apple implementation when game
data is missing. On the Apple TV, open the file-transfer controls in Settings
and note the displayed address. From a Mac on the same network, open the
displayed address in a browser and upload a supported, legally obtained ROM.

The server accepts `.z64`, `.n64`, and `.v64` ROMs, as well as supported `.o2r`
and `.otr` game-data/mod files and saves. The ROM is validated against the
repository’s supported compatibility hashes. It must remain outside the Git
working tree.

After upload, use the Apple TV’s Rescan action if requested. Successful
extraction should create persistent `oot.o2r` application data. The ROM and
Nintendo-derived archive must not be committed, uploaded to source control, or
packaged for distribution.

The Ship support archive `soh.o2r` is separate and is generated by the build
pipeline as described above.

## Playability acceptance test

With a Bluetooth controller connected:

1. Start a new game.
2. Complete the opening sequence.
3. Confirm that Link can be controlled in Kokiri Forest.
4. Verify movement, camera/action controls, A/B/X/Y, triggers, D-pad, and Menu.
5. Verify music, sound effects, pause, local save, relaunch, and Home-to-return.

Record failures and console output in `docs/TVOS_REAL_DEVICE_NOTES.md`.

## Data and source-control hygiene

The repository ignores common ROM and generated archive extensions, but verify
status before committing:

```sh
git status --short
git submodule status
```

Never commit ROMs, `oot.o2r`, `oot-mq.o2r`, or extracted Nintendo assets.
